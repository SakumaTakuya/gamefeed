# ラン画面: テンポと通信エラー（#131）

`docs/requirements.md` の R-8.2-4（幕間 1.0 秒・結果 0.5 秒のテンポ）と R-run.A6-1 の manual 側（通信エラーの画面）、Issue #131 の完了条件に対応する。
項目 ID は `RT-<連番>`。unit で確かめたこと（配線: `apps/web/test/run-controller.spec.ts`、進行: `packages/domain/test/run.spec.ts`）はここでは繰り返さない。ここで見るのは、実機のブラウザで iframe・通信・タイマーが本当につながるかと、人の感覚。

## 前提

- `main` がマージされて Vercel 本番（`https://gamefeed-seven.vercel.app`）にデプロイ済み。ビルドに `VITE_GAMES_ORIGIN` が入っている（試遊ページと同じ値）
- Supabase 本番にマイグレーション `0007`〜`0012` が当たっている（Actions の `db-migrate`）。当たっていないと `POST /api/runs` が失敗し、「ランを作れませんでした（500）」が出る
- **ランに出せるゲームが 1 本以上ある**（#185）。今は公開直後のジョブ（mc#A.9）が無く、公開しただけでは `thumb_key` が NULL のままで新作枠に入らない。確認に使う投稿ごとに次を行う
  1. 試遊ページで遊んで、固まらずに終わることを確かめる（ジョブが見るはずのことを人が見る）
  2. Muse / Claude から `publish_game`（`post_id` つき）で下書きを公開する
  3. GitHub の Actions → `set-thumb-key` → Run workflow に `post_id` を入れて実行する
  4. 実行結果のページ（Summary）に「ランへの出題: new」と出ることを確かめる。下書きのままなら「公開していない投稿です」で失敗する
- 幕間と先読みを見るには 3 本以上あるとよい。1 本でもランは回る（山札 1 本で、手番ごとに周回が進んで速くなる）
- 校正済みが 0 本の間は、どの手番もミスにならない（run#B.10）。ランは 50 手番の上限か、中断で終わる。残機切れ（RT-4）は校正済みのゲームができてから

## 手順

### RT-1 スタートから 1 手番（Mac の Chrome、DevTools を開いて）

1. `https://gamefeed-seven.vercel.app/` を開く
2. Network に `POST /api/runs` → 201。応答に `run_id`・`seed`・`deck` がある。リクエストに `X-Device-Id`（22 文字）が付いている
3. Elements で iframe が 2 枚（山札が 1 本でも 2 枚。同じゲームの 1 周目と 2 周目）。どちらも `sandbox="allow-scripts"`・`referrerpolicy="no-referrer"`・`credentialless` があり、`visibility: hidden`
4. 「タップしてスタート」が出る → タップ
5. 幕間（動詞と入力の種類）が約 1 秒 → ゲームが始まる。ヘッダーに残機（♥♥♥）と「1 本目」
6. ゲームが終わると結果（点。校正中なら「校正中 NN%」）が約 0.5 秒 → 幕間 → 次のゲーム
7. Network に `PUT /api/runs/<id>/turns/0` → 200。本文は `{via: "guest", score, frames, inputs}`

期待: 上のとおり進む。iframe は常に 3 枚以下で、見えているのは 1 枚だけ。

### RT-2 成績表まで（完了条件 1）

1. RT-1 の続きで遊び続ける。校正済みが無い間は 50 手番で終わるので、途中でやめるなら RT-5 の中断を使う
2. ランが終わると「終了」→ 成績表（「NN 本」、総合偏差値、手番ごとの行）
3. Network に `POST /api/runs/<id>/finish` → 200 が 1 回。その前に、遊んだ手番の `PUT turns/<t>` がすべて 200 になっている
4. 「もう一回」で新しいラン（`POST /api/runs` がもう 1 回）。「同じ山札のリンクをコピー」で `/r/<run_id>` がコピーされ、開くと同じ山札のスタート画面になる

期待: 成績表の本数が遊んだ手番の数と一致する。「通信できなかった N 本は記録されていません」は出ない。

### RT-3 通信エラー（完了条件 2）

配信のキャッシュ（60 秒。se#A.5）があるので、山札が少ないと通信を切っても同じゲームがキャッシュから読めてしまう。確実なのは Mac の方法。

Mac の Chrome:

1. DevTools の Network で「Disable cache」を入れ、「Block request URL」に配信オリジン（`VITE_GAMES_ORIGIN` のホスト）を足す
2. `/` をリロードする → 「読み込んでいます…」→ 10 秒ごとに読み込みの skip（`PUT turns/<t>` の本文が `{via: "noload"}`）→ 約 30 秒で「通信エラー」と「もう一回」
3. ブロックを外して「もう一回」→ 新しいランが始まる

iPhone（機内モード）:

1. `/` を開き、1 本目を遊んでいる間に機内モードにする
2. 先読み済みの手番は遊べる。その先が読めなければ、幕間が続いたあと「通信エラー」と「もう一回」が出る（キャッシュから読めた場合は出ない。そのときは 1 分以上置いてからもう一度）

期待: 成績表は出ない。通信を戻して「もう一回」で新しいランが始まる。

### RT-4 残機切れ（校正済みのゲームができてから）

1. わざとミスを 3 回する
2. 3 回目の結果フラッシュに「ミス」が出て、幕間に進まず「終了」→ 成績表（見出しの上に「終了」、ミスの行に印）

### RT-5 中断と再開

1. 遊んでいる途中で別のタブに切り替え、数秒で戻る → 「続きから」と動詞が約 1 秒出て、ゲームが止まったところから続く
2. （任意）別のタブに切り替えたまま 10 分置いて戻る → 「中断」→ 成績表（見出しの上に「中断」）。表示中だった手番は成績表に無い

### RT-6 テンポ（R-8.2-4。iPhone、自分と大学生）

5 本以上遊んで、次を記録する。

- 幕間 1.0 秒は長いか短いか（動詞を読めるか、待たされる感じがあるか）
- 結果フラッシュ 0.5 秒で点が読めるか
- 2 周目以降の速度の上がり方（速くなったと分かるか、理不尽か）
- 到達本数（校正済みのゲームができてから。目標は平均 20〜30 本）
- 「タップしてスタート」が出るまでの時間

### RT-7 連続タップで拡大しない（#190。iPhone の Safari）

1. ランを始め、ゲームの終わり際から幕間にかけて同じ場所を連打する（ダブルタップになるように）
2. 「タップしてスタート」と成績表でもダブルタップしてみる

期待: 画面が拡大しない。成績表は縦にスクロールできる。

### RT-8 ゲームページ（#193・#197、R-run.A14-1〜A14-3。iPhone の Safari と Mac の Chrome）

1. 公開済みの投稿の `https://gamefeed-seven.vercel.app/g/<post_id>` を開く（`publish_game` が公開後に返す `url`。ログインしていないブラウザで）
2. 動詞と題名と作者の `@handle`（#197）と「タップしてスタート」が出る。タップして遊ぶ
3. 終わると点数と「もう一回」が出る。「もう一回」で同じゲームをもう 1 回遊ぶ
4. 「ほかのゲームを続けて遊ぶ」でルート（エンドレスのスタート画面）に移る
5. 下書きの `post_id` と、でたらめな `post_id`（26 文字の ULID の形）で `/g/<post_id>` を開く

期待: 1〜3 はログインなしで遊べる。DevTools の Network に `POST /api/runs` も結果の送信も出ない（単発プレイは記録しない）。5 はどちらも待たずに（#197 より前は 5 秒ほどで）同じ「このゲームは開けません」になる。Network の `GET /api/posts/<post_id>` は 1〜3 が 200、5 が 404。

### RT-9 ゲームページのいいね（#199、R-run.A14-4。iPhone の Safari）

1. 公開済みの投稿の `/g/<post_id>` を開いて 1 回遊ぶ（ログインしていないブラウザで）
2. 結果の幕の「♡ いいね」を押す
3. ページを開き直して、もう 1 回遊ぶ
4. 「作る」側の `list_my_games`（Claude から「自分のゲーム一覧」）でその投稿の `likes` を見る

期待: 2 で、すぐ「♥ いいね済み」になり、もう押せない。3 で、結果の幕が最初から「♥ いいね済み」。4 で `likes` が 1 増えている（同じ端末で何度開き直しても 1 のまま）。

### RT-10 ゲームページの通報（#207、R-run.A14-5。iPhone の Safari）

**注意**: 自動制限（#205）は本番で動いている。解くには運営の `restore`（#209。`docs/status.md`）を呼ぶことになる。ログインした状態で他人の投稿を `性的` / `光の点滅がきつい` で通報しない（信頼スコア 17 以上なら 1 件で制限がかかる）。確認は「その他」か「動作しない」で行う。

1. 公開済みの投稿の `/g/<post_id>` を開いて 1 回遊ぶ
2. 結果の幕の下の「通報」を押す。カテゴリを選ぶ前は「送信」が押せない
3. 「その他」を選び、コメント欄に文字を打って（キーボードが出て、打てる）「送信」
4. 「やめる」で結果の幕に戻れることも見る（別の回で）

期待: 3 の後、結果の幕に戻って「通報しました」と出る。作者のアカウントに結ばれた端末で自分の投稿を通報した場合は「自分のゲームは通報できません」と出る（これも正しい動き）。DB の `reports` に行ができる（匿名なら `weight = 0`。Neon のコンソールで `select * from reports order by id desc limit 5`）。
