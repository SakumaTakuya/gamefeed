# ラン（run）

2026-11-07 作成。前提は `docs/product.md` 3〜4（コアループ、ラン）、9（試遊ページ）と `docs/protocol.md`。読む人は Host（ラン画面・試遊ページ）と API の実装者。
節番号は `run#A.5` のように参照する。A 部が規約、B 部が理由。数値のうち「暫定」と書いたものは定数として持ち、実機で変える。

# A. 規約

## A.1 用語

| 用語 | 意味 |
| --- | --- |
| ラン | スタートから成績表までの 1 回。`run_id` を持つ |
| 山札 | ランの開始時に確定する、出すゲーム（`post_id`）の並び |
| 周回 | 山札を 1 回通ること。エンドレスは周回ごとに速くなる |
| 手番 | ランの中の 1 本。山札の位置と周回で決まる。1 手番 = 1 セッション（`protocol.md`） |
| スロット | 画面上の iframe の置き場。N（表示中）、N+1、N+2 の 3 つ |
| 幕間 | 手番と手番の間に Host が描く画面。次のゲームの動詞と入力アイコン |
| 結果フラッシュ | 手番の終わりに Host が描く 0.5 秒。点と偏差値、またはミス |
| 新作枠 | 山札に 1 本含まれる、校正中のゲーム（`product.md` 7）。成績に入らず残機も減らない。校正済みが足りない間は複数になる（A.2） |
| skip | 読み込み失敗・ゲームの不具合で成立しなかった手番。成績の分母から外れ、残機も減らない |

## A.2 ランの種類と定数

| | エンドレス | デイリー |
| --- | --- | --- |
| 山札の本数 | 12（暫定）。出せるゲームが足りなければ短くなる（下） | 10 |
| 周回 | 上限まで繰り返す | 1 周 |
| 上限（手番） | 50 | 10 |
| 速度 | 周回 k（0 始まり）で `min(1.5, 1 + 0.125 × k)`（暫定）。1/8 刻み | 1.0 固定 |
| 残機 | 3。偏差値 40 未満でミス（閾値は暫定） | なし |
| 新作枠 | 山札に 1 本（足りないときは下） | 山札に 1 本 |
| 記録 | 到達手番数。総合偏差値を併記 | 平均偏差値 |
| 記録になるラン | 毎回 | 同じ山札では初回のみ。2 回目以降は練習（成績表は出るが保存しない） |
| 山札の決め方 | 校正済みの公開ゲームから、直近 7 日（暫定）にその人が引いたものを除いて抽選 | お題と日付から決定論的に |
| 共有 | `/r/<run_id>`。同じ山札で新しいランを作る | `/t/<theme>/<date>`。同じ山札 |

エンドレスの山札が規定どおりに組めないとき（サービス開始直後、校正済みが少ない間だけ起きる）は、あるだけで組む。

- 正規枠（11 本）に校正済みが足りなければ、足りない分を未校正で埋める。埋めた手番は新作枠と同じ扱い（`is_new: true`、`miss_below: null`。残機は減らず、等速の記録は校正に入る）
- 未校正が 0 本なら新作枠なしで、校正済みだけで 12 本にする
- それでも 12 本に満たなければ山札を短くする（最小 1 本。周回は同じ規則で回る）。出せるゲームが 0 本なら `POST /runs` は 409 `no_games`
- 直近 7 日の除外で 12 本組めなくなるときは、引いた日が古いものから除外を外す
- 同じゲームを山札に重ねない

山札の本数より上限が小さい場合（デイリーの 10 本）は 1 周で終わる。エンドレスは 12 本なら 5 周目（速度 1.5）の途中で 50 に達する。

## A.3 ランの作成と手番の発行

ランの進行はサーバが持つ。Host は「次の手番をください」と頼むだけで、山札の位置・周回・速度・新作枠かどうかを自分で決めない。

| 操作 | 内容 |
| --- | --- |
| `POST /runs` | `{mode, theme?, from_run?}`。山札を確定して `run_id` と山札（`post_id` の列、`is_new` の印）を返す。`from_run` は共有リンクからの再現 |
| `POST /runs/{id}/next` | 次の手番を 1 つ発行する。`{turn, post_id, session_id, seed, speed, is_new, lap, miss_below}`。`miss_below` は「この手番で何点未満ならミスか」を発行時点の分布から求めた生の点数（新作枠・校正中・デイリーは `null`）。上限か残機切れなら `{done: true}` |
| `PUT /sessions/{id}/result` | 手番の結果（`protocol.md` の `end` または `via: timeout / error`）。`{score, frames, inputs}` を送り、`{deviation?, miss}` が返る。`miss` は発行時に凍結した `miss_below` で判定した値で、Host の判定と必ず一致する。表示用で、進行には使わない |
| `POST /runs/{id}/finish` | ランを閉じる。凍結した成績表を返す |

- Host は手番 N の `start` を送った時点で N+1 と N+2 の手番を先に発行してよい（先読みのため）。発行済みの手番は、ランが終わればそのまま捨てられる
- `next` の `speed` はサーバが周回から決める。Host はそれをそのまま `init.speed` に渡す。検証（`scoring.md`）はサーバが発行した値を信じる
- `miss_below` は発行時点で凍結し、サーバはセッションに保存する。`result` を受けたとき、サーバは同じ値で判定し直す。ラン中に分布が動いても、その手番の判定は変わらない

## A.4 スロット

| スロット | iframe | セッション状態（`protocol.md` A.5） | ロードするもの |
| --- | --- | --- | --- |
| N | 可視 | RUNNING / PAUSED / ENDED | すべて |
| N+1, N+2 | 不可視 | LOADING → READY → INITED（`start` は送らない） | コードと `required` アセット（上限 512 KB）だけ |
| それ以外 | 存在しない | DESTROYED | — |

- N+1 / N+2 はスロットの位置であって手番番号ではない。skip で手番番号が飛んでも（手番 5 を skip して 6 を出す）、スロットは「表示中」「次に出す」「その次」の 3 つのまま
- 不可視スロットに `start` を送ることはない。`init` は送る（`onInit` まで済ませて待つ）
- 生きている iframe は常に 3 枚以下
- N−1（直前の手番）は持たない。ランは戻れない

## A.5 手番の切り替え

手番 N の終わり（`end` 受理、監視タイマー満了、`error`）から次の手番の `start` まで。順序を変えない。

1. `end` を受けた瞬間に、Host が `score < miss_below` でミスを判定し、残機を減らす（A.7）。通信を待たない。3 機目のミスならこの時点でランの終わりが確定する
2. 結果フラッシュを 0.5 秒（暫定）描く。点と、ミスならその印。同時に `PUT /sessions/{N}/result` を送る（応答の偏差値は届いたら表示に足す。進行には使わない）
3. ランが終わっていれば、幕間の代わりに「終了」を出して `finish` を呼ぶ。以下の手順は行わない
4. 幕間を 1.0 秒（暫定）描く。内容は N+1 の動詞と入力アイコン（`ready` の `verb` / `input`）
5. 幕間の終わりに N+1 が INITED なら `start` を送る。これが唯一の `start` 送信点
6. N+1 がまだ INITED でなければ幕間を延長する。最大 3 秒（暫定）。それでも INITED にならなければ、その手番を skip にして `destroy` し、N+2 を繰り上げ、空いたスロットを 7 と同じく `next` で埋めて（iframe を作って `init` まで進める）4 から繰り返す
7. `start` を送ったら、旧 N に `destroy` を送って iframe を外し、新しい N+2 の手番を `next` で取り、iframe を作って `init` まで進める

結果フラッシュと幕間は Host の描画で、iframe の上に重ねる。この層が Host のものであることを、画面上端の固定ヘッダーと同じ見た目で揃える（ゲームが描く偽 UI と区別するため）。

## A.6 skip

次の手番は skip になる。

| 原因 | 判定する側 |
| --- | --- |
| 幕間の延長上限までに INITED にならない | Host |
| 監視タイマー満了（`protocol.md` A.7、`via: timeout`） | Host |
| `error`（`via: error`） | Host |
| `result` の応答が「このセッションは無効」（セッションの重複、`frames` 超過など、`scoring.md`） | サーバ |

skip の手番は成績の分母に入れず、残機も減らさず、成績表には「—」で出す。ただし**手番は消費する**（上限 50 の 1 つとして数える）。ゲームの記録としては `protocol.md` A.7 のとおり（満了・error は `score: 0` として入る。読み込み失敗は記録しない）。

## A.7 残機とミス（エンドレス）

- ミスは `score < miss_below`。`miss_below` は手番の発行時にサーバが「偏差値 40（暫定）に相当する生の点数」として渡し、Host はこれで `end` の瞬間に判定する。`miss_below` が `null`（新作枠、校正中）の手番はミスにならない。`via: timeout / error` の手番は skip でミスにならない
- サーバも `result` 受信時に同じ凍結値で判定する。Host とサーバの判定は必ず一致する
- 3 回目のミスでランは終わる。Host はその場で「終了」を出し、N の `result` の応答（受理または拒否）を受けてから `finish` を呼ぶ。応答が来なければ 2 回まで再送し（間隔 1 秒、暫定）、それでも来なければそのまま `finish` を呼ぶ（その手番は `abandoned` になり到達本数に入らない。成績表にはその旨を出す）。上限到達・中断からの `finish` も同じ。進行中の先読み手番は捨てる
- `finish` でサーバは手番の順に結果を見て、3 回目のミス以降に発行された手番の結果を記録から捨てる。到達本数はサーバが決める。ミスを無視して遊び続けるクライアントがいても記録は伸びない
- `finish` の時点で結果のない手番（`open`）は `abandoned` にする。到達本数の計算では、最後に結果のある手番より後の `abandoned`（先読みの捨て）は数えず、それより前の `abandoned`（遊んだのに結果を送らなかった手番）は `miss_below` が非 NULL ならミス、NULL（新作枠・校正中）なら skip として数える（`scoring.md` A.9、B.2）
- デイリーに残機はない。10 本を必ず通す

## A.8 速度

- 手番の速度は `next` が返す。エンドレスは周回 k で `min(1.5, 1 + 0.125 × k)`、デイリーは 1.0
- 速度は 1/8 刻みの離散値（1.0, 1.125, 1.25, 1.375, 1.5）。`protocol.md` の `init.speed` はこの 5 値のどれか
- 同じゲームが周回ごとに速くなって戻ってくる。Host は幕間に周回数（「2 周目」）を小さく出す

## A.9 中断と再開

- `visibilitychange` で非表示になったら N に `pause`、表示に戻ったら幕間を出し直してから `resume`。幕間は 1.0 秒で、「続きから」と動詞を出す
- 非表示のまま 10 分（暫定）経ったらランを中断扱いにする。遊んだ手番の結果はそのまま残り、成績表は「中断」として出せる
- ページを閉じた・リロードした場合も中断。ランは再開できない（同じ山札で遊び直すなら `from_run` で新しいラン）

## A.10 新作枠

- 山札には校正中のゲームが 1 本入る（`product.md` 7）。位置はサーバが山札の中でランダムに決める。校正済みが足りず未校正で埋めた手番（A.2）も、以下は新作枠と同じに扱う
- 幕間では区別しない（遊ぶ側に「新作」と知らせない）。結果フラッシュでは偏差値の代わりに `gf:target` との比（`min(1, score / target)`）を出し、「校正中」と添える
- エンドレスで周回が進むと新作枠のゲームも速くなる。2 周目以降（速度 > 1.0）の記録は校正に入れない（`product.md` 5.2）

## A.11 成績表

ランの終わりに `finish` が返す凍結値を Host が描く。Host は計算しない。

| 項目 | エンドレス | デイリー |
| --- | --- | --- |
| 見出し | 到達手番数「23 本」 | 平均偏差値 |
| 科目欄 | 手番ごとの偏差値（または校正中の比、skip は「—」、ミスには印） | 同じ |
| 総合 | 総合偏差値（参考） | 平均偏差値 |
| 共有 | 成績表の画像、`/r/<run_id>` | 成績表の画像、記号列、`/t/<theme>/<date>` |
| 一覧 | 遊んだゲームごとに作者・いいね・通報・ゲームページへの導線 | 同じ |
| 次 | もう一回（新しい山札）、お題一覧へ | もう一回（同じ山札、練習）、次のお題へ |

デイリーの記号列は偏差値を 5 段階に落とした 10 文字。段階の境界は暫定（60 以上 / 50 以上 / 40 以上 / 40 未満 / skip）。

## A.12 試遊ページ（下書き）

下書きのゲームを 1 本だけ遊ぶ Host。ランではないので残機も成績表もない。

- `mode: play` で `init` し、タップで `start`。終わったら結果と「もう一回」。「もう一回」は同じ iframe に `init` し直す（`protocol.md` A.6 の再利用）
- 速度スライダー（1.0〜1.5、1/8 刻み）。動かすと `init.speed` を変えて `init` し直す
- デバッグ表示: フレーム番号、残り時間、`GF.score`、速度、直近の入力（kind と data）、`error` の `message`、`gf:target` との比
- 「診断をコピー」: 直近のセッションについて、`end` が届いたか（届かず監視タイマーで終わったか）、`error` の内容、`GF.score` が 0 のまま終わったか、`frames < time_limit` で終わったか（遅い端末）、速度 1.5 で終われたか、を日本語の箇条書きにしてクリップボードに入れる。AI に貼る前提の文面にする
- 作者のセッションには印を付けて送り、校正に数えない（`product.md` 9）
- 公開ボタンはこのページにある。公開後のゲームページにはデバッグ表示も速度スライダーもない

## A.13 資源制御

- RUNNING は常に 1 枚。CPU を使うのはそれだけ
- 先読みはコードと `required` アセットまで。残りは N になってから。BGM はゲームにない（`game-contract.md` A.6）
- 固まった Guest は `protocol.md` A.7 の監視タイマーで終える。タイマーは Host の `setTimeout` で持ち、Guest が別プロセスで動くブラウザ（Chrome の site isolation）では Guest が無限ループでも発火する。`PerformanceObserver` の long task は補助で、500 ms 以上止まったフレームを数えて「重い」判定（skip と「このゲームは重すぎます」）に使うが、無限ループはタスクが終わらないので long task には現れない。主は監視タイマー
- Guest が Host と同じプロセスで動くブラウザ（iOS Safari）では、Guest の無限ループが Host の main thread も止めるので、監視タイマーも効かない。これはブラウザ側で止める（応答なしの警告）しかない。公開直後にサーバのジョブが決定論ハーネスで 1 回実行し（`mcp.md` A.9）、入力なしで固まるゲームを新作枠に出さない（`calibration = invalid`）ことで頻度を下げる
- 音は「タップしてスタート」で有効化する。初回訪問はミュートで始める（暫定）。Host の音量が `GF.audio.gain` の上限
- iframe の生成は手番の確定（A.5 の 6）で行う。スクロールや予測では作らない

# B. 解説（規則の理由と却下した案）

## B.1 ランの進行をサーバに持たせる理由

速度（`speed`）は検証の入力になるので、Host が自分で決めた値をサーバが信じる形にできない。山札も、共有リンクで同じ順を再現するにはサーバに置くしかない。Host が山札を全部受け取って自分で進める案は、オフラインで進められる利点があるが、速度とミス判定（偏差値はサーバにしかない）の 2 つが Host で決められない以上、利点が小さい。

## B.2 ミスの閾値を発行時に凍結して Host に渡す理由

偏差値は遊んだ人の分布から出す（`product.md` 5.2）ので、分布はサーバにしかない。かといって `result` の応答を待ってから次の手番を始めると、回線が悪いときに幕間で待たされ、テンポが崩れる。逆に応答を待たずに進むと、3 機目のミスの応答が遅れたとき、終わっているはずのランで次の手番が始まる（F8 の違反）。

判定に必要なのは分布そのものではなく「この手番で何点未満ならミスか」という 1 つの数なので、それを手番の発行時に渡せば Host は `end` の瞬間に判定できる。値を発行時点で凍結してサーバにも保存すれば、Host とサーバの判定は同じ入力・同じ閾値で必ず一致する。応答は表示（偏差値）にしか使わず、進行から外れる。

不正（ミスを無視して遊び続ける）は `finish` で防ぐ。サーバは手番の順に結果を見て 3 回目のミス以降を捨てるので、クライアントを改変しても到達本数は伸びない。

結果を送らない手口も同じ場所で防ぐ。3 回目のミスの `result` を送らず次の手番に進めば、サーバはミスを 2 回しか見ない。そこで `finish` では、後ろに結果のある手番より前で結果のない手番を、閾値のある手番ならミスとして数える。正直なクライアントでこれが起きるのは送信に失敗したときだけで、影響は成績表の到達本数に限られる（残機と進行は Host の手元で決まる）。先読みで発行したまま捨てた手番は最後の結果より後ろにあるので数えない。この「最後の結果より後ろ」の判定が成り立つように、Host は表示中の手番の `result` の応答を待ってから `finish` を呼ぶ（A.7）。待たずに呼ぶと、`result` と `finish` の到着順が入れ替わったときに最後の手番が成績表から消える（#77 のレビュー）。形式検証（`verification/Run.tla` F9、#74）はこの規則で検査する。

## B.3 skip が手番を消費する理由

消費しないと、読み込みが遅い端末や固まるゲームが続いたときにランが終わらない（F6）。「50 本」は「50 回の幕間」の意味で、成立した手番の数ではない。成績表の分母からは外すので、記録の意味では損をしない。

読み込みの skip（A.5 の 6）で空いたスロットを `next` で埋めるのも同じ理由。埋めないと、先読み 2 枚が続けて skip になったときに次の手番がなく、ランが終わらない（形式検証 `verification/Run_literal.cfg` で F6 が破れる、#72）。スロットを位置と読めば、生きている iframe は 3 枚を超えない（F3）。

## B.4 戻る操作を持たない理由

テンポを守るため。1 本 3〜10 秒のゲームで「さっきのをもう一回」を許すと、ランの長さも速度の意味も崩れる。遊び直したいゲームはゲームページで単発で遊べる。N−1 の iframe を持たないので、同時に生きる iframe が 1 枚減る副産物もある。

## B.5 山札を 12 本にした理由（暫定）

周回の意味を作るため。エンドレスの面白さは「同じゲームが速くなって戻ってくる」駆け引きで、プールが数百本だと 50 手番では一周しない。12 本なら 4〜5 周で、1 周目は初見、2 周目から慣れが効き、5 周目は 1.5 倍で苦しい、という山ができる。本数は初見の多さと慣れの効き方のトレードオフなので実機で変える。

## B.6 幕間で「新作」を知らせない理由

知らせると遊ぶ側が手を抜く。新作枠の目的は校正用の記録を集めることなので、本気で遊んでもらう必要がある。残機が減らないことは結果フラッシュで分かれば十分。

## B.7 速度を 1/8 刻みにした理由

連続値にすると、リプレイの再現と検証のためにセッションごとに任意の実数を保存することになる。5 値なら `speed` の意味を人が読めるし、`protocol.md` の未解決（離散か連続か）もここで閉じる。

## B.8 先読みを `required` アセットまでにする理由

N+1, N+2 の 2 枚ぶんを常に裏でロードしている。全アセット（3 MB）を 2 枚ぶん読むとモバイル回線で手番より通信が長くなる。`required` の上限 512 KB で、先読みは最大 2 × 640 KB 程度に収まる。MVP ではアセット自体がないので実質コードだけ。

## B.9 中断したランを再開できない理由

再開には山札の位置・周回・残機・発行済みの手番をサーバが保持し、Host が iframe を作り直す必要がある。10 分の中断後に速度 1.375 の 4 周目から再開する体験は、遊ぶ側にも良くない。中断の結果はそのまま成績表になり、同じ山札で遊び直すのは `from_run` で足りる。

## B.10 校正済みが足りないとき、未校正で埋める理由（#123）

サービス開始時は校正済みが 0 本で、未校正のゲームが記録を集める場所は新作枠しかない。規定どおり「校正済み 11 本 + 新作枠 1 本」を要求すると、ランが始まらず、どのゲームも校正されない。埋めた手番はミスにならないので、校正済みが 0 本の間のエンドレスは「ミスの起きない 50 手番」になるが、身内で校正を踏む期間の話なので受け入れる。校正済みが 11 本を超えれば、この規則は使われなくなる。

却下した案: 運営が手で `calibrated` にする（n < 20 で偏差値が出てしまい、`scoring.md` A.5 と食い違う）。ゲームページの単発プレイで踏んでからランを開く（ランを試せるのが 12 本 × 20 プレイの後になる）。同じゲームを山札に重ねる（1 周目から同じゲームが戻ってきて、周回と速度の意味が崩れる）。
